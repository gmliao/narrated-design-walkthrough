# Live demo deployment: narrated-design-walkthrough-example

## Goal

Ship a public, clickable demonstration of the `narrated-design-walkthrough` skill so that anyone evaluating it can experience the output without installing anything. The demo lives in a **separate repo** to keep this skill repo focused on the tool itself and to model the real "user installs the skill in their own repo" flow.

## Motivation

The skill turns engineering design docs into 8–12 minute narrated walkthroughs. Its value is qualitative (browse-by-ear, spotlight-anchored stage direction) and not conveyable by text descriptions. Without a live URL to point at, every conversation about whether to adopt this skill stalls on "I'd need to install it first to see what it does." A hosted GitHub Pages demo removes that gate.

The sample's source design doc itself addresses the real pain that motivated this skill in the first place — **"設計文件太多看不完"**. So the demo doubles as the skill's own origin story and as proof that the skill solves the problem it claims to.

## Non-goals

- Hosted TTS (the demo relies on browser Web Speech API; quality varies by browser).
- MP4 recording (deferred per user decision; SKILL.md already documents the manual recording path).
- CI-enforced sync between skill repo and demo repo (requires skill to expose a deterministic CLI first; out of scope).
- Multi-language switcher (Chinese walkthrough + English landing only; both content types are single-version).

## Deploy pipeline (`.github/workflows/deploy-pages.yml`)

```yaml
name: Deploy walkthroughs to Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'

      - name: Install Slidev dependencies
        working-directory: docs/walkthroughs
        run: npm install --no-audit --no-fund

      - name: Validate all walkthroughs
        working-directory: docs/walkthroughs
        run: npm run validate

      - name: Build each walkthrough with base path
        working-directory: docs/walkthroughs
        env:
          REPO_BASE: /narrated-design-walkthrough-example
        run: |
          mkdir -p ../../site
          cp index.html ../../site/
          # `npm run --silent list` first line is "Available walkthroughs:", rest are 2-space-indented slugs
          for slug in $(npm run --silent list | tail -n +2 | sed 's/^[[:space:]]*//'); do
            echo "→ building $slug with base $REPO_BASE/$slug/"
            npm run build "$slug" -- --base "$REPO_BASE/$slug/"
            mkdir -p "../../site/$slug"
            cp -r "$slug/dist/." "../../site/$slug/"
          done

      - uses: actions/upload-pages-artifact@v3
        with:
          path: site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

### Pipeline notes

- **Trigger**: push to `main` + manual `workflow_dispatch`. No PR previews in v1.
- **Discovery**: `npm run list` auto-finds walkthroughs; adding `docs/walkthroughs/<new-slug>/slides.md` is sufficient — no workflow edits.
- **Base path**: `--base /narrated-design-walkthrough-example/<slug>/` is required so Slidev's asset URLs resolve under the Pages subpath. Without it, all assets 404.
- **Validation gate**: `npm run validate` runs before any build, so structural issues fail the workflow loudly (better than shipping a broken slide nobody saw).
- **`site/` location**: assembled at repo root (parent of `docs/`) to keep the artifact upload path simple.
- **No `gh-pages` branch**: `actions/deploy-pages@v4` consumes the artifact directly; nothing committed to the repo.
- **No `package-lock.json` committed**: matches template's gitignore. Trade-off: minor version drift between CI runs is possible because `npm install` resolves caret ranges fresh. Acceptable for a demo — if Slidev minor upgrade breaks the build, the live URL fails visibly and we react. A production deploy would commit the lockfile and use `npm ci`; we don't, because the demo is not load-bearing.
